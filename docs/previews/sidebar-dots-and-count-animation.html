Two things went with them. The hover card that used to hang off a channel's counts has no trigger any more, so live session detail now lives in one place: the status bar, which keeps its own hover card. And Threads has no unread indicator at all — that is the one call I made past the literal ask, and it is a four-line revert if you want the dot back.

2 · The status bar

Flash, as picked. A count that rises lights up in place for 700ms and fades. A count that falls lands silently — a session finishing on its own is the one thing nobody needs pulled out of the corner of an eye.

The highlight is painted with a box-shadow spread rather than padding, so a count lighting up never nudges its neighbours along the bar. It is drawn from currentColor, which keeps it legible in both themes without a second palette — try the dark toggle and replay.

A state sitting at zero is hidden rather than unmounted, so the jump from nothing to one still registers as a rise and gets its flash. That was the one thing worth getting right: 0 → 1 needs input is the transition most worth catching.

Typecheck clean, 269 tests passing, and the production build emits the keyframes. It has not been driven in a running app — this worktree has no .env, so the build stops at DATABASE_URL right after compiling.

Reduced motion is honoured: with the OS setting on, the flash does not play and the pulsing dot holds still. This page obeys it too, so if the replay above looks inert, that is why.
